## 一、用户反馈修复：预览窗口工具栏按钮显示不完整

### 根因（三处叠加，MarkdownPreviewForm.Designer.cs）

1. **表单硬编码 7.8pt 字体**：`Font = new Font("Segoe UI", 7.8F, ...)`。工具栏/状态栏全部继承该小字体，而在系统字体更大或 DPI 缩放（125%/150%）环境下，GDI 按系统度量排版文本，与 Designer 按 7.8pt 序列化的固定尺寸（工具栏高 27px、按钮 24px 高）失配 → 文本/图标垂直裁切。
2. **图标被放大绘制**：图标源为 16px 位图（`Save_16x_32` 等），`ImageScalingSize = 20×20` 强制放大到 20px，加剧工具栏高度压力且发虚。
3. **Grip 占位**：`GripStyle` 默认显示，白白占约 22px 宽度。

### 修复

- 表单字体改由构造函数**在 `InitializeComponent` 之前**设 `SystemFonts.MessageBoxFont`（与 SettingsForm 同一修复方式）——工具栏/状态栏创建时即继承系统字体，按钮文本按系统度量完整排版，任何 DPI/字体组合下不再裁切；同时满足此前"字体与系统一致"的要求。
- `ImageScalingSize` 20×20 → **16×16**（图标原生尺寸，清晰且降低工具栏高度）；三项按钮显式 `DisplayStyle = ImageAndText`、`tbPreview.AutoSize = true` 显式化、`GripStyle = Hidden`（释放宽度）。

### 附带修复（独立审查中发现，同批提交）

1. **IE11 引擎外链缺口**（P3，已修复）：v1.2 系列的"外链一律转交系统浏览器"只落在 WebView2 控件；IE11 控件的 `webBrowserPreview_Navigating` 对非 `about:blank` 导航**不做任何处理**——IE11 引擎下点击 http(s) 外链仍会在面板内导航，劫持预览视图。已按同一策略补齐：取消导航 + `UseShellExecute` 转交系统浏览器（`IE11WebbrowserControl.cs`）。
2. **ExportToHtml 空渲染守卫**（防御性）：预览尚未完成首次渲染时 `currentMarkdownText == null`，菜单导出会沿渲染链抛异常；已在 `ExportToHtml(HtmlExportMode)` 入口加 null 早退守卫（`MarkdownPreviewForm.cs`）。

### 与 v1.2.3–v1.2.5 导出重构的合并说明

本修复与团队并行推进的导出模式重构（`HtmlExportMode` 枚举、工具栏 5 按钮直出：Save As / Single File / Images Saved / Copy / PDF）经变基融合：工具栏显示修复（系统字体 / 16px 原生图标 / GripStyle Hidden / 显式 AutoSize + ImageAndText）完整叠加在新的 5 按钮结构上——按钮数量从 3 增至 5，本修复对宽度/高度裁切的治理更为必要；导出实现以团队版本为准，仅补入空渲染守卫。

## 四、结论

1. 按钮显示不全的根因（硬编码小字体 + 放大位图 + 固定尺寸）已消除，修复方式与 SettingsForm 一致，系统字体下不再依赖任何硬编码度量。
2. 其他团队 0d14597 九项改动全部核实成立、质量良好；其"外链转系统浏览器"在 IE11 引擎的覆盖缺口已补齐。
3. 本轮共 3 个修复（工具栏显示、IE11 外链、导出空渲染守卫）+ 1 项审查结论，无遗留 P1/P2；修复已变基于 v1.2.5 之上，工具栏治理叠加在团队新的 5 按钮直出结构上。
